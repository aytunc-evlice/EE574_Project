# EE574 Semester Project – AC-WLS Power System State Estimator

## Overview

This project implements a realistic **AC Weighted Least Squares (WLS) State Estimator**
for an Energy Management System (EMS), applied to the IEEE 14-bus test network extracted
from the IEEE 30-bus Common Data Format file. The estimator supports PMU integration,
numerical observability analysis, and normalized-residual bad data detection.

### Features implemented

| Requirement | Module |
|---|---|
| AC-WLS state estimation (Newton-based) | `src/estimator.py` |
| PMU phasor measurement integration | `src/simulation.py` |
| Numerical observability analysis (SVD rank check) | `src/observability.py` |
| Bad data detection & identification (normalized residual test) | `src/bad_data.py` |
| Three-scenario comparison | `run_pipeline.py` |
| Multi-case comparison across arbitrary networks | `compare_cases.py` |
| Test case generation and validation suite | `testing/` |

## Time-Varying Measurement Stream

`gen_measurements.py` generates a realistic **stream of measurements that change
in time** from any CDF case, matching the project scenario: **PMU phasors every
1 s, SCADA every 5 s**. The true network state genuinely evolves — the loads are
scaled by a load profile and the **AC power flow is re-solved at every instant**
(`src/powerflow.py`, a from-scratch Newton-Raphson solver) — and noisy
measurements are then sampled from that true state.

```bash
# Generate a 60 s stream (PMU @1s, SCADA @5s) from the IEEE 14-bus network
python gen_measurements.py --cdf ieee_cdf_sample.dat --out results/timeseries/demo

# Drive the WLS estimator across the stream and plot it tracking the moving state
python run_timeseries.py --dir results/timeseries/demo
```

Each snapshot is written as a standalone file in the **same 8-section format as
`measure.dat`** (`read_me_meas.txt`), so any single instant is runnable with the
static pipeline (`python run_pipeline.py --meas <snapshot.dat>`).

**Per-measurement noise model.** Every measurement channel is assigned **its own
σ once**, drawn from a per-type range, and that σ is **held constant for the
whole run** (a meter's accuracy class does not drift). Different channels differ
(`V1` ≠ `V2`, `P12` ≠ `P3`); only the noisy *value* is redrawn each instant. The
full assignment is saved to `sigmas.csv`. Default ranges:

| Channel | σ range (pu) |
|---|---|
| SCADA Vmag | 0.008 – 0.012 |
| SCADA Pinj/Qinj/Pflow/Qflow | 0.015 – 0.025 |
| PMU Vmag/Vang | 5e-5 – 2e-4 |
| PMU Imag/Iang | 1e-4 – 5e-4 |

**Outputs** (under `--out`, default `results/timeseries/<case>/`):

| File | Contents |
|---|---|
| `pmu/pmu_t*.dat` | PMU snapshots — Vmag, Vang (+ Imag, Iang current phasors) |
| `scada/scada_t*.dat` | SCADA snapshots — Vmag, Pinj, Qinj, Pflow, Qflow |
| `index.csv` | `t_sec, kind, n_meas, lambda, file` for the whole stream |
| `truth.csv` | ground-truth `V/θ` per timestamp (to score the estimator) |
| `sigmas.csv` | the frozen per-channel σ assignment |
| `manifest.json` | full run configuration (cadence, seed, profile, PMU buses) |

**Key options:** `--horizon` (s), `--pmu-dt`, `--scada-dt`, `--seed`,
`--pmu-buses`, `--inj-buses {gen,all}`, `--drop-pmu-prob` (missing PMU frames),
`--no-pmu-current`, `--diurnal-amp`, `--loads-in-pu`.

> **Load scaling.** Most cases store Load/Gen columns in **MW** (the
> `cdf_gen.py`-generated `case_3BUS/5BUS/RAND*` and the genuine
> `ieee_cdf_sample.dat`); the parser's `÷ MVA base` is correct for them and they
> come out at realistic `read_me_meas.txt` scale with **no flag**. The exception
> is **`case_IEEE14.dat`**, whose Load column holds standard IEEE per-unit values
> (e.g. `0.94`) rather than MW (`94.2`), so it alone needs **`--loads-in-pu`**:
>
> ```bash
> python gen_measurements.py --all testing/cases/                       # 7 cases, MW-correct
> python gen_measurements.py --cdf testing/cases/case_IEEE14.dat --loads-in-pu   # the pu-labeled one
> ```
>
> Using `--loads-in-pu` on the MW cases would multiply their loads ×100 and the
> power flow will not converge — apply it only to genuinely per-unit files.

The time-series loader (`src.parser.load_timeseries` / `parse_measurement_file`)
reads these files positionally so empty sections are handled correctly, and
`src.parser.fuse` combines the latest SCADA scan with the current PMU frame for
each estimator update.

## Bad-Data Streams

`inject_bad_data.py` takes a clean stream and writes a corrupted **twin** beside
it (the clean data is never modified), so you have matched clean/bad datasets.
Each file gets up to `--max-bad` gross errors (default **2** → at most 4 across a
SCADA + PMU pair at one instant):

- **persistent broken meters** — a fixed channel per stream carries the *same*
  fault (a recurring gain or polarity fault) in every file;
- **transient spikes** — extra random channels are corrupted one file at a time.

Each gross error is made **unmistakably** wrong relative to the truth — never a
small perturbation that could pass for noise:

- **scale** — `bad = factor · clean` with `|factor| ∈ [--scale LO HI]` (default
  **≥ 10×** the real value);
- **negate** — `bad = −clean` (polarity reversal), chosen with prob `--negate-prob`.

Voltage magnitude (`Vmag`) is special-cased to a large **positive** multiple only
— a meter cannot read a negative `|V|`, and a negated PMU voltage is an extreme
self-masking leverage point. A σ floor (`--min-sigma`, default 10) guarantees the
change is gross even when the true value is near zero. **Exactly which
measurements are bad is reported** in `bad_log.csv`.

```bash
python inject_bad_data.py --dir results/timeseries/case_RAND20   # one case
python inject_bad_data.py --all results/timeseries               # every clean case
```

**Outputs** in `results/timeseries/<case>_bad/` — same `pmu/`, `scada/`,
`index.csv` (now with an `n_bad` column), plus copies of `truth.csv`/`sigmas.csv`:

| File | Contents |
|---|---|
| `bad_log.csv` | one row per injected error: `t_sec, kind, file, mode, style, factor, type, loc1, loc2, sigma, clean_value, bad_value, error, error_sigmas, pos` |
| `manifest_bad.json` | config + the persistent broken meters + totals |

**Options:** `--max-bad 2`, `--n-persistent 1`, `--scale 10 30`,
`--negate-prob 0.5`, `--min-sigma 10`, `--scope {both,scada,pmu}`, `--seed`.
Reproducible for a given `(seed, args)`.

> **Detecting gross errors.** A ×10–30 error on a high-weight (tiny-σ) PMU channel
> is an extreme leverage point: a plain WLS solve *fits* it and smears the
> inconsistency onto good neighbours. `solve_timeseries.py` therefore runs a
> **gross-error pre-screen** — it gates each measurement's innovation against the
> tracked state (seeded from the network-model base-case load flow) and drops the
> solve-destroying outliers (`--prescreen-gate`, default 300 σ) before the WLS
> solve; the normalized-residual loop then removes the moderate errors at proper
> sensitivity. This keeps precision ≈ 1.0 and recall ≈ 0.9–1.0 across all cases,
> and even catches the PMU voltage-angle errors that a residual-only test misses.

## Comparing Results Across Multiple Cases

`compare_cases.py` runs the estimator on every case in a folder and produces
a side-by-side metrics table, a three-panel comparison plot, and a CSV file.

```bash
# Compare all 8 clean test cases (default)
python compare_cases.py

# Compare a specific folder
python compare_cases.py testing/cases/

# Compare the corrupted-model cases
python compare_cases.py testing/cases_bad/

# Compare hand-picked files
python compare_cases.py testing/cases/case_3BUS.dat testing/cases/case_RAND40.dat

# Save to a custom output folder
python compare_cases.py --out my_results/
```

**Metrics reported per case:**

| Metric | Description |
|---|---|
| Buses / Branches / States | Network size |
| Rank / Observable | Jacobian rank vs n_states (full observability check) |
| SC2 Iters | Newton iterations to converge on clean synthetic data |
| SC2 J | WLS objective value — should be ≈ degrees of freedom (meas − states) |
| SC2 RMSE\_V / RMSE\_θ | Voltage/angle accuracy vs load-flow reference |
| BD Detected | Whether the injected +0.5 pu gross error is flagged (|r̄| > 3.0) |
| BD Correct ID | Whether the largest residual identifies the injected measurement |
| SC3 RMSE\_V | Voltage accuracy after bad-data removal |

**Outputs saved to `results/`:**
- `comparison.png` — grouped bar charts (RMSE, WLS objective J, observability rank)
- `comparison.csv` — all metrics as a spreadsheet

## Testing Infrastructure

The `testing/` folder contains a complete validation suite for the estimator.

### Generating test cases

```bash
# Generate 8 clean CDF cases (3-bus to 40-bus random networks)
python testing/cdf_gen.py

# Generate 103 corrupted-model cases (14 fault types × 8 base cases)
python testing/cdf_corrupt.py
```

The cases in `testing/cases/` and `testing/cases_bad/` are already generated
and committed. You only need to re-run these if you delete them.

### Validating the estimator

Run these three commands in order:

```bash
# Step 1 — Check that all input CDF files are structurally valid
python testing/check_cdf.py

# Step 2 — Run the estimator on all clean cases, get PASS/FAIL per case
python testing/validate_cases.py

# Step 3 — Run the main project pipeline (the actual deliverable)
python run_pipeline.py
```

### What `validate_cases.py` checks

For each clean test case, four checks are performed:

| Check | Meaning |
|---|---|
| **O** Observable | Synthetic SCADA+PMU has full Jacobian rank |
| **C** Converged | WLS finds a solution (warm-started from load-flow) |
| **R** Recovered | Estimated state matches true state within RMSE < 0.01 |
| **B** Bad data detected | Injected +0.5 pu gross error flags above threshold 3.0 |

The `B` flag carries a lowercase suffix for sequential-removal auto-recovery:
`y` = the injected measurement is correctly removed and state recovers;
`x` = detected but removal order is wrong (interacting bad-data topology).

A case **PASSES** on O + C + R + B. The `x` suffix on `RAND10` is a known
limitation of the largest-normalized-residual method on low-redundancy meshed
networks — not a bug.

### Corrupted-model cases (`testing/cases_bad/`)

Each corrupted case applies exactly one labeled fault to a clean base network.
There are 14 fault types across three categories:

| Category | Faults |
|---|---|
| **A — Branch parameters** | Tap ratio off by ~2% or ~20%, R/X swapped, impedance ×10 |
| **B — Topology** | Wrong endpoint, transformer orientation flipped, branch deleted, branch duplicated |
| **C — Bus data** | PV→PQ type flip, voltage out of range, load unit confusion (×0.01), load/gen swapped, spurious shunt, duplicate bus number |

Each corrupted file is accompanied by a `.json` manifest recording the exact
change. Use `compare_cases.py testing/cases_bad/` to see how each fault
affects estimation accuracy.

## Methodology

### State Vector

**x = [θ₂ … θₙ, V₁ … Vₙ]** (2N−1 states; θ₁ = 0 is the slack bus reference)

For the 14-bus network: 13 angles + 14 voltages = **27 states**.

### AC-WLS State Estimation

The estimator minimises the weighted least-squares objective:

```
J(x) = (z − h(x))ᵀ W (z − h(x))     W = diag(1/σᵢ²)
```

Each Newton iteration solves the normal equations:

```
(HᵀWH) Δx = Hᵀ W (z − h(x))
```

where H = dh/dx is the analytically computed Jacobian. The step size α is
found by **backtracking line search** (halved until J decreases), which
prevents divergence far from the solution.

All estimations use **warm start** from the load-flow solution stored in the
CDF file — standard EMS practice that achieves convergence in 2–3 iterations.

### Transformer π-Model

Off-nominal tap ratio τ on the from-bus side gives asymmetric shunt elements:

```
Y[i,i] += y/τ² + jb_sh     (tap side)
Y[j,j] += y    + jb_sh     (impedance side)
Y[i,j]  = Y[j,i] = −y/τ
```

Branch flow measurements in either direction use the correct g_ii = g/τ²
(tap side) or g_ii = g (impedance side), handled by `_branch_coefs()` in
`src/network.py`.

### PMU Integration

PMU measurements provide both voltage magnitude and phase angle directly,
with accuracy ~100× better than SCADA (σ_PMU = 0.0001 pu vs σ_SCADA = 0.005–0.01 pu).
For the 14-bus case, PMUs at buses **{2, 5, 9, 10, 12, 14}** bring the
Jacobian rank from 19 to 27 (fully observable) with 45 degrees of redundancy.
For arbitrary networks, PMUs are placed at every 3rd non-slack bus.

### Observability Analysis

The system is observable if and only if rank(H) = n_states. Rank is computed
numerically via SVD at flat start. Buses with no measurement coverage are
identified by scanning the measurement list.

### Bad Data Detection

After convergence, the normalized residual for each measurement is:

```
r̄ᵢ = rᵢ / √Ωᵢᵢ     where Ω = R − H(HᵀWH)⁻¹Hᵀ
```

Under clean conditions r̄ᵢ ~ N(0,1). Values with |r̄ᵢ| > 3.0 are flagged.
The measurement with the largest |r̄ᵢ| is removed and the estimator re-runs.

## Scenarios (IEEE 14-bus)

### Scenario 1 – Original SCADA (Unobservable)

Uses the 19 measurements from `measure.dat` (sections 1–6, slack-bus angle
excluded). The Jacobian has **rank 19/27** — buses 9, 10, 12, and 14 are
unobservable. Large normalized residuals (|r̄| > 10 000) reflect the
model–measurement mismatch: `measure.dat` was created for the full 30-bus
network and is inconsistent with the 14-bus sub-model.

### Scenario 2 – Synthetic SCADA + PMU (Fully Observable, Clean)

Synthetic measurements are generated from the 14-bus load-flow (Gaussian noise
σ_V = 0.005 pu, σ_PQ = 0.01 pu) plus PMU phasors at buses {2, 5, 9, 10, 12, 14}
(σ_PMU = 0.0001 pu), yielding **72 measurements** for 27 states (45 redundant).

- Converges in **2 iterations**
- **RMSE voltage = 0.00055 pu**, RMSE angle = 0.016°
- **0 measurements exceed the bad-data threshold**

### Scenario 3 – Bad Data Detection and Identification

A gross error of **+0.5 pu** is injected into the Pflow(1→3) measurement.

- Largest normalised residual: **Pflow(1→3), |r̄| = 44.9** → correctly identified
- After removing the bad measurement and re-estimating: RMSE voltage = 0.00054 pu,
  RMSE angle = 0.018° (matches clean Scenario 2)

### Summary Table

|---|---|---|---|---|---|
| 1 – Original SCADA | 19 | 19/27 | YES* | 25101 | N/A |
| 2 – Synthetic SCADA + PMU | 72 | 27/27 | YES | 42.4 | — |
